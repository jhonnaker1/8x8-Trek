# Per-port text for the Commodore Plus/4, applied to c128/src/strings.txt by:
#
#     python3 tools/gen_strings.py --override plus4/src/strings.override.txt OUT
#
# IDS THAT ALREADY EXIST, AND NOTHING ELSE -- the generator owns the numbering,
# so this port builds the same strdata.h and the same STR_COUNT as every other.
# A hand-appended duplicate once silently stole another string's id; see
# amiga/src/strings.override.txt. And NOTES.md item 60 for what STR_COUNT is
# load-bearing for: the binary and the STRINGS.DAT beside it are coupled by it,
# and a mismatch plays with every label blank rather than complaining.
#
# Only the strings that NAME THE MACHINE differ.

# The title bar. The 40-column build draws S_330, not S_0 -- see ui_title().
330	COMMODORE PLUS/4 PORT

# S_0 is the 80-column title bar, which this port never compiles. Overridden
# anyway so that nothing on this disk says C128 about a Plus/4: a string that
# is unreachable today is a string somebody reaches tomorrow. Same precedent
# as c64/src/strings.override.txt.
0	 COMMODORE PLUS/4 PORT 

# The dedication line, drawn at x=0 on row 23 of the 40-column title.
82	TO THE PLUS/4.

# THE FAREWELL. The C128's wording says "BASIC IS ON THE 40-COLUMN SCREEN",
# which is a C128 sentence about its OTHER display; this machine has one
# screen. And plat_exit() here banks the ROM back in and takes the machine's
# own reset vector, because the game has been running with RAM mapped over
# BOTH ROMs and there is no BASIC to return to until that happens -- so what
# comes back is a fresh boot, not the BASIC that started the game.
#
# It also names the keypress: main() waits for one here and the C128's wording
# never says so, which leaves the player looking at a dead screen. The MEGA65
# and the C64 both hit that and their overrides both say so.
10	HIT A KEY AND THE PLUS/4 RESTARTS.
